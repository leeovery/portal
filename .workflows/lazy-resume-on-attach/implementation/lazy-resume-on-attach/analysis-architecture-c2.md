- FINDING: The hydrate helper's resume decision is a shared mutable pointer that each tail must remember to finish, and the exec step cannot check that it was finished
  SEVERITY: low
  FAILURE: Two silent outcomes for the user whose pane is restored, and neither emits a WARN. (1) Any path that reaches execShellOrHookAndExit with a nil Decision fires a lazy registration eagerly. A lazy registration then starts its process at boot with no panel, which is the resident cost the feature exists to remove. The mode the user set is ignored. (2) Any tail that reaches the exec without going through markPendingThenUnsetSkeletonMarker leaves Decision.Wait true with Exe and Pane empty. The pane then parks on `'' state resume-draw …`, which exits 127. The backstop hands the pane a bare shell. The registration neither fires nor waits, and nothing records why. The only way to notice is a user asking why their resume did not come back.
  FILES: cmd/state_hydrate.go:61-65, cmd/state_hydrate.go:70-75, cmd/state_hydrate.go:112, cmd/state_hydrate.go:244-262, cmd/state_hydrate.go:272-284, cmd/state_hydrate.go:318-352, cmd/state_hydrate.go:358-386, cmd/state_hydrate_lazy_test.go:454-479
  DESCRIPTION: The invariant "a pane waits only if its marker is written and its chain is composed" is spread across three functions, and they are joined by a pointer mutated through by-value copies of hydrateConfig. runHydrate resolves the decision. markPendingThenUnsetSkeletonMarker then downgrades Wait and fills in Exe and Pane through that pointer. The comment on the field states this: "held by pointer so a refusal taken inside a by-value handler reaches the exec". That mark step is not called from one place. It is called separately by the replay path, by handleHydrateTimeout and by handleHydrateFileMissing. The last two are replaceable function seams on the config, and tests do replace them. execShellOrHookAndExit then acts on Decision.Wait and trusts that one of those three calls ran. It has no way to tell a marked, composed decision from one that was never finished. execResumeChainAndExit adds a third assumption: it calls cfg.DisableTTYSignals() unguarded, after the marker is written, even though the struct's other function fields are nil-tolerant. The `Decision == nil` branch is unreachable in production, because runHydrate always sets Decision. Its only caller is tests, and TestHydrateLazy_NilDecisionFallsBackToItsOwnLookup pins its behaviour ("want the hook … even for a lazy registration"). So production code carries a second resolution route that ignores the resume mode. Resolved/marked/parked is a small state machine, and it is currently encoded as fields that are valid only in some states, with no type enforcing the transitions.
  RECOMMENDATION: Make the decision a value the pipeline passes along instead of a pointer each step mutates. (a) Take markPendingThenUnsetSkeletonMarker out of handleHydrateTimeout and handleHydrateFileMissing and call it once in runHydrate, after whichever handler returns. Ordering is unchanged, because both handlers return nil as their last act. The handlers then only log and clean up. (b) Have the mark step return the final decision. It should report "wait" only as a parked-chain value that carries exe and pane, and that value should exist only once the marker is written. (c) Change execShellOrHookAndExit to take that decision as a required parameter and delete the nil branch, along with the test that pins eager firing for a lazy registration. With these changes, a new tail that skips the mark step does not compile, and a lazy registration has only one route to the exec.

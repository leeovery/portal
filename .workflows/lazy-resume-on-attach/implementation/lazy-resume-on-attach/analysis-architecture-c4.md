AGENT: architecture
FINDINGS:
- FINDING: A waiting pane's saved transcript is unprotected between restore and its pending mark, so a capture landing in that window deletes it
  SEVERITY: medium
  FAILURE: After a cold boot, a pane that was waiting at shutdown is restored from `scrollback/pane-<token>.bin`. It only gets the token-keyed carry-forward back after its hydrate helper has finished replaying, slept 100ms and set the pending marker. Until then, only the skeleton merge carries its record forward, and that merge matches by address. Two captures miss the pane during that window. The first is `portal state commit-now`, which tmux's session-closed hook fires whenever any session closes (for example, the user culling a finished session in the picker's first seconds). It passes a nil skip set, so it builds the pane a positional record. The second is the daemon's first tick after the restore. That tick always captures, because a fresh daemon's LastSaveAt is zero, and it misses any pane that restore gave a different address from the one it was saved at. The non-contiguous-window reboot suite shows that this happens. Either commit then garbage-collects `pane-<token>.bin` as unreferenced. The helper replays from the file descriptor it already holds, so this boot looks right. The pane then goes pending, and from then on nothing recaptures it. The token merge treats the missing file as adoptable (ENOENT counts as adoption), so sessions.json names a file that no longer exists, and nothing logs it. At the next reboot the pane restores empty under its panel, and the user's transcript is gone for good. If a helper's FIFO signal failed, the file is deleted before the helper opens it, and the pane comes back blank on this boot too.

  DESCRIPTION: Two carry-forward rules protect a frozen pane's saved record, and they meet at a seam. The skeleton merge is keyed by address and lasts a few seconds. It applies only when the caller supplies the skeleton set, and it covers a pane until its helper finishes. The frozen merge is keyed by token, lasts indefinitely and covers the pane from the pending mark onwards. Before this feature the first rule could afford to miss. A mid-restore pane it skipped was recaptured from its live content one tick after its skeleton marker cleared, so a saved file the GC had removed was rewritten a second later. A pane that goes pending is never recaptured, so a miss by the first rule now means permanent loss, of exactly the transcript the freeze exists to keep. Both production callers of CaptureAndRefile miss in this way. commit-now deliberately passes a nil skipSet, and its suite pins that. The daemon's address match cannot follow a pane that restore renumbered. The eager signal pass does not wait for replay, so hydration runs past the point where @portal-restoring clears. The identity the merge needs is already present, because restore re-stamps the token on the live pane before arming it, so the live row carries the token throughout hydration.
  RECOMMENDATION: Close the seam in `internal/state`, not in the callers. (1) When a skeleton-marked pane carries a token, carry its previous record forward by that token, using the same takePrevRecord lookup as mergeFrozenPanes. Fall back to the address match only for a pane with no token, so the hand-over from restore to wait is keyed on identity from start to finish. (2) Make it impossible to leave out the skeleton set. Either have CaptureAndRefile read the set itself (both production callers hold a *tmux.Client, which already lists server options), or at minimum have commit-now read the set and pass it as the daemon does, treating a failed marker read as a failed commit through its existing failCommitNow route. A real-tmux integration case would pin the gap: a pane that waited across a reboot, captured by commit-now and by a renumbered restore before its helper marks it pending.
SUMMARY: The resume chain, the store's two shapes, the picker's pending read and the preview's token resolution all compose cleanly. Their shared rules each have a single home (hand-off to hook or shell, the probe-then-read pane option, the pending-scrollback path, the act keys). The one structural gap is the hand-over between restore and the wait. There, a waiting pane's re-filed transcript is carried forward only by an address-keyed merge, which commit-now skips and a renumbered restore defeats. Because the freeze stops the saver from ever recapturing the pane, one missed capture becomes permanent loss of the transcript.

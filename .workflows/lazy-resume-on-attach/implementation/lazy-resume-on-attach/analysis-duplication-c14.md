  FAILURE: A change to one copy's EINTR retry or recomputed window that misses the other passes every test. No test in either package reaches the EINTR branch, and no test names `awaitTTYInput`, `selectBoundedReader`, `awaitReadable` or `armStdinRead`. Resizing the pane is what exercises that branch. tmux delivers SIGWINCH to the pane's foreground group, the Go runtime installs a handler for it in every process, and select(2) returns EINTR after a handler on darwin and linux even with SA_RESTART set. Suppose the cmd copy stopped retrying. A resize inside the waiter's 50ms quiet window would end the listen with an error, and the loop would judge the arrival as it stands. A paste whose first byte is `d` would then open the discard confirmation, and one whose first byte is a line break would resume the pane. Both are answers the panel exists to refuse. With no byte pending, the waiter would exit, and the recovery tail would drop the pane to a plain shell without running its resume. The same regression in the draw's input drain would replace the discard confirmation with a "can't clear pending input" report. Suppose instead the tui copy stopped retrying. A resize during the 50ms appearance probe would make it resolve dark, painting a light terminal's pane in the dark palette. In every case the user sees a panel that changed or vanished on a resize, and nothing logged points at the wait.

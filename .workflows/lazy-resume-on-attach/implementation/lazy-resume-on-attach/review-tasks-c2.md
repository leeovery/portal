# Review Tasks: Lazy Resume On Attach (Cycle 2)

## Task 1: Hold the resume panel on an alternate screen whatever the pane's `alternate-screen` setting
severity: high
sources: 5-the-resume-panel-6-answering-the-panel-1, 14-1-1, test-surface-1

**Problem**: The draw writes the alternate-screen enter (`hydrateAltScreenEnter`, `\e[?1049h`, `cmd/state_resume_draw.go:60`) and paints the whole pane. Every route out then leaves through `hydrateResetPreamble` (`\e[?1049l`): Enter and a confirmed discard (`resumeUnfreeze`, `cmd/state_resume_wait.go:378`), the recover tail (`cmd/state_resume_recover.go:46`) and the backstop (`parkedChainBackstop`, `cmd/state_hydrate.go:290`). Nothing reads or pins tmux's `alternate-screen` option, and a restored pane inherits `set -g alternate-screen off`. Under that setting tmux ignores both sequences, so the card is painted onto the primary grid over the replayed transcript's visible screenful. This was measured on a disposable tmux 3.7c socket and re-measured by the assessor: with the option off, `capture-pane -a -p` answered `no alternate screen`, and after the leave `capture-pane -p -S -` held the card's rows with the hook's output run onto the last of them and both real lines gone. The card stays after Enter, a confirmed discard or a recovered waiter, and the hook's output prints below it. Once the pending marker clears, the saver captures the card in place of that screenful, so the next reboot restores the damaged history. Lazy is the shipped default, so this reaches every hook-carrying pane on such an install. The same measurement showed that `set-option -p alternate-screen on` on the pane, over a global `off`, keeps the transcript intact. Coupled test gap: in `TestHydrateLazy_FiresTheHookWhenThePaneCannotBeMarked` (`cmd/state_hydrate_lazy_test.go:278-315`), the rows "TMUX_PANE is absent" and "the executable cannot be resolved" never assert that no `@portal-resume-pending` write was issued. Moving `SetResumePendingMarker` ahead of `resolveExe()` in `markResumePending` was measured to leave `go test ./cmd` green. An install where `os.Executable()` fails would then have every lazy pane marked pending while it execs its hook, and its scrollback would never be written again.

**Solution**: Pin the option on the waiting pane rather than falling back to eager. That choice follows from the specification. The panel must sit on the alternate screen and leave no trace in the history, and lazy ships on so that an upgraded install meets panels rather than processes. Its eager fallback is for a pane that cannot be protected, and a pane Portal can pin can be protected. Eager stays as the fallback for a pane tmux will not pin. The settled shape:
- **Mark step.** In `markResumePending`, after the pane and the executable resolve, pin `alternate-screen on` pane-scoped (`set-option -p`), then write the pending marker. The pin is written unconditionally, with no read first. On a pane already `on` it changes nothing, and a read to skip it would add a read to save a write and a second path to test.
  - A pin that fails is a refusal like the existing ones: no marker is written, the hook fires eagerly, and the one existing `set resume pending marker failed` WARN names the pin's error.
  - The pin goes before the marker because a marker that cannot be taken back freezes the pane's saved scrollback for life, while a pin left behind only overrides one display setting on one pane.
  - If the marker write fails after the pin landed, lift the pin at once. The pane never entered the alternate screen, so no ordering applies there. A failed lift gets its own WARN.
- **Leave routes (Enter, confirmed discard, recover tail, backstop).** The pin comes off last, in this order: the leave bytes, then the pending-marker clear, then tmux confirming the pane is off the alternate screen, then the unset. tmux confirms by `#{alternate_on}` reading `0` on a short bounded poll.
  - The order is observed rather than assumed. An unset that tmux processes before the `\e[?1049l` makes tmux ignore the leave, which strands the pane on the alternate screen with the card over the transcript, and the saver captures that.
  - When Enter's or a discard's marker clear is refused, the pin stays, because the redraw of the panel that follows needs it.
  - A leave not confirmed within the bound also keeps the pin: the pane keeps `alternate-screen on`, which is the lesser failure. The waiter or recover tail records a WARN.
  - A failed unset gets a WARN, and the answer proceeds.
  - The backstop takes the same steps in shell form after its marker clear: a bounded poll of `#{alternate_on}`, then the unset, with errors discarded and no record, since no Portal binary is left to write one.
- **Guard conditions.**
  - Compose every new `-t` through `tmux.PaneIDTarget`, including inside the backstop's shell argv (`TestTmuxTargetsAreComposedThroughTheExactnessVocabulary`).
  - Word each new WARN apart from `unset resume pending marker failed`, which `TestRunResumeRecover_FailedClearRecord` permits at exactly one production site.
  - `state_resume_wait.go` and `state_resume_recover.go` keep their import and call bans (no hooks, prefs, theme or tui), so the `alternate_on` read and the unset there go through the tmux client alone.
- **Refusal table.** In `TestHydrateLazy_FiresTheHookWhenThePaneCannotBeMarked`:
  - Set `opts.Commander = commandertest.Quiet()` before `refusal.prepare`, and add a per-row `wantNoWrite` that runs `assertNoPendingMarker(t, cmder)` after `lazyRun`.
  - Narrow `assertNoPendingMarker` to the `@portal-resume-pending` option. It currently matches any `set-option -p`, which the pin now issues.
  - `wantNoWrite` is true for "TMUX_PANE is absent" and "the executable cannot be resolved". Those two rows also assert that no pin was written, since a pin written ahead of resolution would outlive the eager hook.
  - `wantNoWrite` is also true for a new row, "the alternate-screen pin fails".
  - The existing "the marker write fails" row's `Fails("set-option", "-p")` would now fail the pin first. Narrow it to fail the marker write alone, with the pin succeeding, and have it assert that the pin was lifted. It replaces the commander in its own prepare and skips the no-write check, as today.
- **Real-tmux case.** Add a case to the existing lazy-resume integration suite (`internal/restore/lazy_resume_panel_integration_test.go`) on its `tmuxtest` `-S` socket, with `alternate-screen off` set globally before restore. The unit suite cannot observe tmux's option, so this case is the only one that can. That file is already `//go:build integration` and builds its binary through `restoretest`. It already calls `IsolateStateForTest` and `RegisterStateDirTeardownGuard` before `tmuxtest.New`, and the new case keeps all of that (`TestTeardownGuardCoversEveryServerHostingFixture`, `TestBuildHelpersStayInTheIntegrationLane`). The case asserts:
  - While the panel waits, the transcript is intact underneath it (`capture-pane -a -p`).
  - After Enter, a confirmed discard and a recovered waiter, the transcript shows with no card on screen or in `capture-pane -S -`.
  - Once answered, the pane carries no pane-level `alternate-screen`.

**Outcome**: With `set -g alternate-screen off`, a lazy pane still waits behind its panel with its transcript untouched underneath. Answering reveals the transcript with no card on screen or in the saved history, and the pane goes back to the user's own `alternate-screen` setting. A pane tmux will not pin comes back eager, and the one refusal WARN names why.

**Acceptance Criteria**:
- [ ] With a lazy registration, on each of the three tails (replay, signal timeout, scrollback missing), the helper pins `alternate-screen on` on the pane with a pane-scoped `set-option -p`, then writes `@portal-resume-pending`, then clears the pane's mid-restore marker, and parks the pane on its chain. No read of the pane's `alternate-screen` comes before the pin.
- [ ] With no registration, or one resolving eager, every tail restores exactly as today, and the pane is written neither the pin nor the pending marker.
- [ ] A lazy pane with `$TMUX_PANE` absent, or whose executable cannot be resolved, runs the eager hook (`sh -c 'echo hi; exec $SHELL'`) with one `set resume pending marker failed` WARN naming the pane and the error. It is written neither the pin nor the pending marker.
- [ ] A lazy pane whose pin tmux refuses runs the eager hook with one `set resume pending marker failed` WARN naming the pane and the pin's error. It is written no pending marker.
- [ ] A lazy pane whose pin lands and whose pending-marker write is then refused runs the eager hook with the one refusal WARN naming the marker's error, and the pin is lifted (`set-option -pu … alternate-screen`) before the hook runs. If tmux refuses the lift too, a second WARN, worded apart from the refusal, names the pane and the lift's error, and the hook still runs.
- [ ] Enter on the waiting panel does four things in this order before it runs what the store holds: it writes the leave sequence, clears the pending marker, reads `#{alternate_on}` on a short bounded poll until it reads `0`, and unsets the pane's `alternate-screen` (`set-option -pu`). A confirmed discard takes the same four steps in the same order, after its removal and before it drops the pane to a plain shell.
- [ ] Enter or a confirmed discard whose marker clear is refused redraws the waiting panel carrying the reason, as today, and leaves the pin in place.
- [ ] The recover tail, on a pane still marked, writes the leave sequence, clears the marker, confirms `#{alternate_on}` reads `0`, unsets the pin, and then execs the user's shell. On a pane no longer marked it does nothing at all, as today.
- [ ] On Enter, a confirmed discard or the recover tail, two failures are recorded and neither stops the hand-over. If `#{alternate_on}` has not read `0` when the bound runs out, the pane keeps its pin and one WARN names the pane. If tmux refuses the unset, one WARN names the pane and the error. Either way the pane is still handed to the hook or the shell. Neither WARN reads `unset resume pending marker failed`, which stays emitted by exactly one production site (`TestRunResumeRecover_FailedClearRecord`).
- [ ] A parked chain whose tail cannot start takes the same steps in shell form, after it clears the pending marker and before it hands over the user's shell. It polls `#{alternate_on}` for a bounded time and unsets the pane's `alternate-screen` once that reads `0`; a pane that never reads `0` within the bound keeps its pin. The chain writes nothing to stderr and still reaches the shell when tmux refuses or is absent from `PATH`. A chain whose tail started still leaves the backstop inert.
- [ ] Every `-t` the change composes names the pane through `tmux.PaneIDTarget`, the backstop's shell argv included (`TestTmuxTargetsAreComposedThroughTheExactnessVocabulary`). `state_resume_wait.go` and `state_resume_recover.go` pass their import and call guards unchanged.
- [ ] On a real tmux server with `alternate-screen off` set globally before restore, a restored lazy pane shows the panel on screen while `capture-pane -a -p` returns its pre-reboot line intact underneath.
- [ ] On that server the pane is answered three ways: Enter, a confirmed discard, and a waiter that ended without answering and is recovered by the chain's tail. After each, the pane's screen shows its pre-reboot transcript, neither the screen nor `capture-pane -S -` holds any line of the card, and the pane carries no pane-level `alternate-screen`.

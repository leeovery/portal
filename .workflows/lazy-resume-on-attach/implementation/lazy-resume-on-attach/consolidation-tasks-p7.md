# Consolidation Tasks: Lazy Resume On Attach (Phase 7)

## Task 1: A Pane Whose Waiter Died Lands at a Usable Shell by Either Route
placement: phase 7
severity: behaviour

**Problem**: Phase 7 gave a pane whose waiter died two routes to the user's shell, and each one skips part of what the pane needs. The pane then comes up unusable, and on the second route its scrollback also stops being saved.
- **The Go recovery tail** (`runResumeRecover`, `cmd/state_resume_recover.go:35-62`) turns only signal generation back on (`setStdinSignals` → `setTTYSignals`, `cmd/tty_signals.go:18-20`). A waiter holds the tty raw (`cmd/state_resume_wait.go:114-119`, put back only by its deferred `cfg.restore()`), and `MakeRaw` also clears ICANON, ECHO, IEXTEN, ICRNL, IXON and OPOST. A waiter ended by a signal never runs its deferred restore, since it notifies SIGWINCH alone (`cmd/state_resume_wait.go:430-436`). Such signals include `pkill portal`'s SIGTERM (which hits every waiting pane at once), an OOM or jetsam SIGKILL, and a group SIGINT/SIGQUIT the parked chain's trap routes into the tail. The user then lands at a shell on a raw terminal: typed input does not echo, output staircases, and nothing but `reset` fixes it.
- **The shell backstop** (`parkedChainBackstop`, `cmd/state_hydrate.go:299-302`) runs when the tail cannot start because the binary is gone from the baked path. It restores the tty with `stty sane` but skips the tail's other two steps:
  - It never leaves the panel's alternate screen or shows the cursor again (every draw enters the one and hides the other, `hydrateAltScreenEnter` at `cmd/state_resume_draw.go:60`), so the shell starts over the stale card with no visible cursor.
  - It never clears `@portal-resume-pending`, so the saver skips this pane's scrollback for the rest of the pane's life (`paneSkipsScrollback`, `cmd/state_daemon.go:273` and `:322-327`). The picker dot and doctor's pending count stay up, and nothing is logged.

  The specification says a marker wrongly left set is reachable one way, and that way is recorded; this is a second way, unrecorded. The backstop is reached by any unanswered waiter while the baked binary is missing: a killed waiter, or a `d`, Escape, resize or report redraw whose exec of the missing path fails (`resumeRedraw` → `resumeHandOff` → `defaultExecShell`, which exits 1 at `cmd/state_hydrate.go:393-398`; the tail's own exec of the missing path then fails 127). A Linuxbrew upgrade is one trigger, since it removes the versioned Cellar path `os.Executable` resolved.

The route tests pin only the ISIG seam call (`cmd/state_resume_signals_test.go:302-341`) and a `stty sane` plus a shell (`cmd/state_resume_backstop_test.go:82-120`), so neither gap is visible.

**Solution**: Both routes end in the same pane state: a cooked terminal, the primary screen, a visible cursor, and the pending marker cleared. That state is derived from the specification's statement that the recovery tail "drops the pane to a usable prompt", and from its rule that a marker wrongly left set has one recorded route. Both routes build on the settled cycle-1 directions: signal generation stays held off across the chain, and the backstop is keyed to the tail's could-not-run statuses. Neither direction changes.
- **The Go tail** restores cooked input and output modes, not only ISIG, through a sibling of `setTTYSignals` in `cmd/tty_signals.go`. The sibling goes through the same `updateLocalModes`-style termios updater and sets back what `MakeRaw` clears that a shell needs: Lflag `ICANON|ECHO|ECHOE|ECHOK|ISIG|IEXTEN`, Iflag `ICRNL|IXON`, Oflag `OPOST|ONLCR`. It becomes the recovery tail's seam in place of `setStdinSignals`. The Enter and confirmed-discard answers stay on `setStdinSignals`, because they restore the tty the waiter found before handing off, so ISIG is all they owe.
- **The backstop** takes the tail's two missing steps, in the tail's order, before its `stty sane` and shell:
  - it writes `hydrateResetPreamble`;
  - it unsets `@portal-resume-pending` on the pane with `tmux set-option -pu -t <pane>`, with errors discarded.

  Both steps are composed from the same Go values the tail uses: `hydrateResetPreamble`, `state.ResumePendingOption`, `tmux.PaneIDTarget` of the payload's pane, and `shellquote`. That keeps the two routes from drifting. `parkedChainBackstop` therefore takes the payload.
- **Known gap:** the backstop route still cannot log a WARN, because no Portal binary is left to emit one.
- **Docs:** CLAUDE.md's Resume hooks description of the parked chain is updated to show the trap and the backstop.

**Outcome**: A pane whose waiter died reaches the same state by either route: the user's shell on a cooked terminal, on the primary screen with its transcript and a visible cursor, and with its pending marker cleared. The saver resumes capturing the pane, and the picker and doctor stop reporting it as waiting.

**Acceptance Criteria**:
- [ ] A waiting pane whose tty was left raw by a waiter that never ran its restore (ended by SIGTERM, SIGKILL, or a group SIGINT/SIGQUIT the parked chain's trap routes into the tail) is handed the user's shell by the recovery tail on a cooked tty: Lflag `ICANON`, `ECHO`, `ECHOE`, `ECHOK`, `ISIG`, `IEXTEN`, Iflag `ICRNL`, `IXON` and Oflag `OPOST`, `ONLCR` are all set, so typed input echoes, Enter submits a line, Ctrl-C interrupts a foreground program and output lines start at column 0
- [ ] A pane answered by Enter or by a confirmed discard is handed on exactly as today: the tty the waiter found is put back and only signal generation is turned back on
- [ ] A parked chain whose tail cannot start — the binary gone from the baked path, or still there but no longer executable — does these in order before the user's shell starts: writes `hydrateResetPreamble` to the pane (cursor shown, alternate screen left, SGR reset); runs `tmux set-option -pu -t <pane id> @portal-resume-pending` for the payload's pane (`-t %7` for pane `%7`); runs `stty sane`; then starts `${SHELL:-/bin/sh}`. The chain exits with that shell's status
- [ ] On that same could-not-start route, a marker clear that fails — `tmux` exiting non-zero, or absent from `PATH` — does not stop the route: `stty sane` and the user's shell still follow, and nothing the failed clear wrote to stderr reaches the pane
- [ ] A parked chain whose tail did start — a pane answered on the panel, or a tail that recovered the pane and whose shell then exited with any status, 126 and 127 included — closes on that shell's first exit: no reset bytes written, no `tmux` clear and no `stty` run, no second shell, and the chain exits with that status

**Do**:
- `cmd/tty_signals.go`: add a sibling of `setTTYSignals` (`:18-20`) that sets Lflag `ICANON|ECHO|ECHOE|ECHOK|ISIG|IEXTEN`, Iflag `ICRNL|IXON` and Oflag `OPOST|ONLCR`, through the same termios updater (`updateLocalModes`, `:22-29`, which already hands its update the whole `unix.Termios` read through `ioctlReadTermios`/`ioctlWriteTermios`, `cmd/tty_termios_{darwin,linux}.go`), with a stdin form beside `setStdinSignals` (`:35-37`).
- `cmd/state_resume_recover.go:97`: wire that stdin form as the tail's `EnableTTYSignals` seam in place of `setStdinSignals`. `runResumeRecover`'s steps and their order (`:38-61`: marker read, `hydrateResetPreamble`, clear with its `unset resume pending marker failed` WARN, terminal restore through `enableTTYSignalsOrLog`, shell) are unchanged.
- The waiter's Enter and confirmed-discard answers (`resumeAnswerEnter` / `resumeAnswerDiscard`, `cmd/state_resume_wait.go:315-363`, wired at `:494`) stay on `setStdinSignals`. Signal generation stays cleared across the chain (`execResumeChainAndExit`, `cmd/state_hydrate.go:279`), unchanged.
- `cmd/state_hydrate.go:292-302`: `parkedChainBackstop` takes the payload. Inside its existing could-not-run arm (status `126|127` and `[ ! -x <exe> ]`), before `stty sane 2>/dev/null; exec "${SHELL:-/bin/sh}"`, it writes the reset as `printf '%s' ` + `shellquote.Single(hydrateResetPreamble)`, then clears the marker as `shellquote.Join([]string{"tmux", "set-option", "-pu", "-t", string(tmux.PaneIDTarget(p.Pane)), state.ResumePendingOption})` + ` 2>/dev/null`. Both are composed from those Go values, with no literal restated. The status keying, the executable check, the `exit $s` pass-through and `parkedChainTrap` are unchanged. The pane's environment carries the `TMUX` and `PATH` the helper's own tmux calls used.
- The signature change reaches every composer of the backstop. `rg -n 'parkedChainBackstop\(' --type go` returns 4 lines: the definition (`cmd/state_hydrate.go:299`), `parkedResumeChain` (`:308`), and the test composers `cmd/state_hydrate_lazy_test.go:119` and `:271`.
- The backstop route gains no log record: no Portal binary is left to emit one.
- These routes are already exercised on a real pty in `cmd/tty_signals_pty_test.go` (darwin) and in `cmd/state_resume_backstop_test.go`, which runs the parked chain under `/bin/sh` with a stubbed `stty` and user shell on `PATH`; a stubbed `tmux` joins those stubs.
- `CLAUDE.md`, "Resume hooks": the parked chain is described as `/bin/sh -c '<draw argv>; <recover argv>'`, a parked shell running the draw followed by the tail. Update it to show the `trap : INT QUIT` prefix and the backstop: on a tail that could not start, reset, marker clear, `stty sane`, the user's shell.

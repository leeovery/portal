# Consolidation Tasks: Lazy Resume On Attach (Phase 9)

## Task 1: One Declaration of Where a Waiting Pane's Transcript Lives
placement: phase 9
severity: near-miss

**Problem**: The picker preview's reader (`internal/tui/preview_adapter.go:28-29`) restates both halves of the re-file rule `internal/state` owns: which panes get a token-named file (the `nanoid.IsTokenShaped` gate `refilePendingPane` applies, `internal/state/scrollback.go:121-125`) and where that file sits (`PendingScrollbackFile` joined onto the state dir through `FromSlash`, the unexported `joinStored`, `internal/state/scrollback.go:175-177`). If the state side changes either half, every affected waiting pane previews `(no saved content)` for its whole wait again — or, for a pane tmux has moved, the capture of the pane now at its old address — which is the defect task 9-5 fixed. Nothing would fail: the state tests never exercise the preview, and the preview's tests build the token-file path with the same copied composition (`internal/tui/pagepreview_waiting_pane_test.go:25`, `:145`).
**Solution**: Declare the rule once in `internal/state`, extending phase 2's direction that the token-derived name is declared only in `paths.go`: add `PendingScrollbackPath(dir, token string) (path string, ok bool)` beside `PendingScrollbackFile`, with `ok` false when the token is not token-shaped and `path` the stored relative name joined onto `dir` as `joinStored` joins it. `refilePendingPane` takes its gate from `ok` and keeps `PendingScrollbackFile` for the relative form the record stores; the preview adapter replaces its copy with one call and drops its own gate and join. A pure refactor — the same files are read and written as today.
**Outcome**: The saver's re-file and the picker preview answer "which file holds this waiting pane's transcript" from one function, so a change to either half reaches both. No file is read or written differently from today, and every existing re-file and preview test passes with its assertions unchanged.

**Acceptance Criteria**:
- [ ] A waiting pane whose token the pane-token mint produced, with its bytes still at its positional file, is re-filed on the next capture exactly as today: its record names `scrollback/pane-<token>.bin`, the bytes sit in that file, and the `TestRefilePendingScrollback` and `internal/state/capture_refile_test.go` suites pass unchanged
- [ ] A waiting pane whose token is absent, too short, too long or outside the id alphabet keeps its positional record, its positional file and its dedup entry through a re-file, with nothing logged, as today
- [ ] Pressing Space on a session holding a waiting pane previews what it previews today in every case the `TestPreviewWaitingPane_*` suite pins: a re-filed pane's token-named file whether or not tmux moved it, the positional file before the pane is re-filed, the read error for a token-named file that exists but cannot be read, and the positional file for a pane carrying no token, a token the rule refuses, or no wait
- [ ] `state.PendingScrollbackPath(dir, token)` for a minted token answers ok, with a path naming the file under `dir` that the saver's re-file moves that pane's bytes into
- [ ] `state.PendingScrollbackPath` answers not-ok for an empty token, a token one character short, and a token that climbs out of the scrollback directory (`/../../<token>`)
- [ ] Rule form: the token-shape gate and the join of the token-named file onto the state directory are declared once, in `PendingScrollbackPath` — `internal/tui/preview_adapter.go` calls neither `nanoid.IsTokenShaped` nor `state.PendingScrollbackFile`, and `refilePendingPane` calls no `nanoid.IsTokenShaped` of its own

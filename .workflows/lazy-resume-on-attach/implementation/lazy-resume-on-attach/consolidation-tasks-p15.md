# Consolidation Tasks: Lazy Resume On Attach (Phase 15)

## Task 1: Corrections
placement: phase 15
severity: corrections

**Problem**: CLAUDE.md's "Resume hooks" paragraph (CLAUDE.md:190) is loaded into every agent session as the authoritative account of the resume chain, and it states the chain's steps as closed lists that no longer match the landed code. The lazy branch names only the pending marker; the recovery tail is "leaves the panel's screen, clears `@portal-resume-pending`, restores a cooked terminal and exec's the user's shell"; the backstop's steps are listed exactly as reset bytes → `tmux set-option -pu … @portal-resume-pending` → `stty sane` → `${SHELL:-/bin/sh}`; and the eager downgrade's causes are "an absent `$TMUX_PANE`, an unresolvable executable or a failed marker write". The chain now pins a pane-level `alternate-screen on` before the marker (cmd/state_hydrate.go:394), lifts it when the marker write is refused (:397-400), and every route off the panel's screen — Enter and a confirmed discard (cmd/state_resume_wait.go:386), the recovery tail (cmd/state_resume_recover.go:56) and the shell backstop (cmd/state_hydrate.go:291-316, `backstopReleasePin`) — unsets it only once `#{alternate_on}` reads `0` within a bounded poll (cmd/state_resume_altscreen.go:39-58). An agent working from the paragraph would read the pin, the poll and the unset as undocumented residue or as drift from the stated step order and strip or reorder them, leaving panes on an install with `set -g alternate-screen off` painting the card into their saved transcript, or an unset landing before tmux processes the leave and stranding the card over the transcript. Only the integration lane (`TestLazyResumePanel_HoldsThePanelOnAnAlternateScreenTheInstallTurnedOff`, internal/restore/lazy_resume_panel_integration_test.go:275) would catch it, and nothing runs that lane automatically. The reviewer of task 15-1 raised the same gap; CLAUDE.md is unchanged since phase 13, so the pin, the poll and the unset are all still missing from line 190.

**Solution**: One edit to CLAUDE.md:190, amending four sentences in place and leaving the rest of the paragraph alone — derived from the landed code and the specification's §5.1/§8.2 as corrected this pass:
- CLAUDE.md:190, lazy branch — the pane is first pinned to a pane-level `alternate-screen on` (so the panel sits on an alternate screen whatever the install sets) and then marked `@portal-resume-pending`, both before the mid-restore marker is cleared; the pin goes first because a pin left behind overrides one display setting on one pane while a marker left behind freezes that pane's scrollback.
- CLAUDE.md:190, recovery tail — after the marker clear the tail lifts the pin only once tmux reports `#{alternate_on}` `0` within a bounded poll, before the cooked terminal and the shell; an unconfirmed leave keeps the pin, because an unset tmux processes before the leave bytes makes it ignore the leave. Enter and a confirmed discard take the same release after a clear that landed, and a refused clear keeps the pin for the redraw.
- CLAUDE.md:190, backstop step list — insert, after the marker clear and before `stty sane`, the bounded `#{alternate_on}` poll followed by `tmux set-option -pu -t <pane> alternate-screen` only once it reads `0`, errors discarded.
- CLAUDE.md:190, refusal list — add a refused alternate-screen pin among the causes that downgrade to eager under the same `set resume pending marker failed` WARN, and state that a refused marker lifts the pin it follows (a refused lift logs its own `lift alternate-screen pin failed` WARN).

**Outcome**: CLAUDE.md's Resume hooks paragraph describes the resume chain as the code runs it — the pane-level `alternate-screen on` pin written before the pending marker, the confirmed-leave release on every route off the panel's screen, the backstop's release step between the marker clear and `stty sane`, and the refused pin among the eager-downgrade causes — so an agent reading it finds the pin, the poll and the unset documented in the order the code takes them. No code, test or behaviour changes.

- FINDING: The commit lock is enforced only by prose, because the unlocked primitives it wraps are still exported
  SEVERITY: medium
  FAILURE: A future committer can bypass the lock and lose a waiting pane's transcript without anyone noticing. Examples of such a committer: a new save or flush command, a doctor repair, or a harness promoted to production. It would be written against the exported `state.CaptureAndRefile` + `state.Commit` (or `state.CaptureStructure` + `state.Commit`). Every step compiles and behaves correctly in isolation, and every existing test stays green. But that committer would take no `commit.lock`, so it reopens exactly the interleaving phase 12 closed. Its capture, re-file and housekeeping pass interleave with the daemon's locked cycle or with commit-now's. When the two committers disagree on whether a pane is still mid-restore or already pending, the second one's `gcOrphanScrollback` deletes the `pane-<token>.bin` the first one just filed. A frozen pane is never capture-paned again, so nothing rewrites the file. The user finds out only at the next reboot, when the panel comes up over an empty pane. The only thing standing between a new committer and that loss today is one sentence in CLAUDE.md ("Calling `CaptureAndRefile` and `Commit` directly reopens the interleaving").
  FILES: internal/state/commit.go:17-44, internal/state/scrollback.go:88-118, internal/state/scrollback.go:267-288, internal/state/commit_cycle.go:45-72, CLAUDE.md:61
  DESCRIPTION: `RunCommitCycle` is the right abstraction. It owns the lock span from the skeleton-marker read to the end of the housekeeping pass, calls `LoadPrev` under the lock, and bounds the acquire. But the package still exports the three unlocked pieces it composes, and each is a complete committing step on its own:
    - `Commit`, the sole deleter of scrollback files in the tree.
    - `CaptureAndRefile`.
    - `RefilePendingScrollback`.
  None of the three has a production caller outside `internal/state`. The daemon tick, the shutdown flush and commit-now all go through `RunCommitCycle`, and `CaptureAndRefile`/`RefilePendingScrollback` are reached only from inside the package. So the exported surface no longer describes how the package may be used. It offers a composition that type-checks and silently breaks the invariant the lock exists for. Correctness now depends on each future caller having read CLAUDE.md, not on the API. That runs against the codebase's own practice, where rules of this weight get a structural fence rather than prose: the target type, the seam guard, the colour-literal guard, and the leaf-dependency guards.
  RECOMMENDATION: Make `RunCommitCycle` the only committing entry point the package exports.
    - Unexport `CaptureAndRefile` and `RefilePendingScrollback`. Neither has a caller outside `internal/state`. Its black-box tests reach them through `export_test.go` aliases, which already bridges `StubRenameNoReplaceUnsupported`.
    - Fence `Commit` in one of two ways:
      - Preferred: unexport it. Tests that only seed `sessions.json` move to the existing `restoretest.WriteIndex`. The `cmd/bootstrap` `runDaemonTick` helper and the realtmux capture test commit through `RunCommitCycle` with a `Dump` closure, which also brings the helper onto the production cycle.
      - Alternative: keep it exported and add a `sourceguardtest`-driven guard that fails any non-test file outside `internal/state` calling `state.Commit`, `state.CaptureAndRefile` or `state.RefilePendingScrollback`.
    - Once the fence exists, shorten the CLAUDE.md warning to name it.

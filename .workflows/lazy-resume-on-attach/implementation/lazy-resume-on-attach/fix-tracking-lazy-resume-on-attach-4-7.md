The install's cycle is `ListSkeletonMarkers` → `CaptureStructure` → **`state.RefilePendingScrollback`** → per-pane dump → **`state.Commit`** (which runs `gcOrphanScrollback` over `ComputeReferencedSet`) — see `cmd/state_daemon.go:243-257` and `cmd/state_commit_now.go:120-132`. Compounding it, the fixture's tokens (`lazysubjecttoken` / `eagercontroltoken`, lines 31-32) are 16-17 bytes, while `nanoid.paneTokenWidth` is 6 — so `refilePendingPane`'s `IsTokenShaped` gate (`internal/state/scrollback.go:119-121`) would return early even if the refile call were added, and a real `portal hook set` pane always carries a 6-byte minted token. Net effect: the subtest at line 180 ("it keeps the waiting pane's transcript…") and the second restore at line 196 both run against a positional `scrollback/lazysubject__0.0.bin` that production would have renamed to `scrollback/pane-<token>.bin` on the first frozen tick, and the assertion at line 182 (`record.ScrollbackFile == fx.subjectScrollbackRel`) asserts the opposite of what the spec says the record holds. The failure this leaves uncovered is exactly the one the task's own edge case calls silent: a break in the rename, in the record's carried path, or in the GC's reading of the referenced set ships undetected, and the user who reboots twice while a pane waits gets an empty pane with no copy of the transcript anywhere. The helper's own doc comment (lines 366-369) states the property the code does not have — "the same code path the install runs".

  FAILURE: A fix or change made to one copy's EINTR retry, remaining-window recomputation or FD_SETSIZE precondition, and not to the other, passes every test, because no test in either package exercises the EINTR path. Both processes that run these waits take SIGWINCH while they wait, since a resize is what the waiter is watching for. If the cmd copy stops retrying, a resize that lands inside the waiter's 50ms quiet window ends the wait. The recovery tail then drops the pane to a plain shell without running its resume. If that window held the first byte of a paste, the byte is judged as a lone key, so a paste opening with `d` puts up the discard confirmation. The same regression in the drain replaces the confirmation with a "can't clear pending input" report row. If the tui copy stops retrying, a light terminal's pane is drawn in the dark palette. In every case the user sees a panel that vanished or changed on a resize, and nothing points to the cause.

  DESCRIPTION: Two tasks each wrote the same readiness wait over a terminal descriptor. `cmd/tty_drain.go:awaitTTYInput` backs the input drain and the waiter's quiet window. `internal/tui/pane_appearance.go:selectBoundedReader.awaitReadable` backs the appearance probe.

Land the deferred `type Target string` in `internal/tmux`: the exact-target constructors return it, every `-t`-taking client method and cross-package holder takes it, and the source guard reduces to the residue the type cannot express.

ACCEPTANCE CRITERIA:
1. A plain `string` no longer satisfies a `-t` parameter anywhere in `internal/tmux`'s exported surface; the compiler rejects a hand-composed target.
2. All four exact-target constructors return `Target`, and `PaneTarget`/`windowTarget` still return `string`.
3. Every composed argv is byte-identical to before the change — the type is a compile-time property with no runtime effect.
4. The source guard no longer restates any rule the type expresses, and what remains of it passes.
5. `cmd`, `internal/state`, `internal/restore` and `internal/session` compile and pass with no behaviour change.

STATUS: issues_found

SPEC CONTEXT: This is a phase-9 implementation-analysis task, so its authority is its own body rather than the specification (the spec's Corrigenda section carries nothing about target composition; `TargetExact` appears nowhere in it). The standing invariant it protects is the one CLAUDE.md's `tmux` row states and that phases 1–5 established: tmux prefix-matches a bare `-t`, so `-t foo` silently resolves to a live `foo-2` once `foo` is gone — on the kill path that destroys the wrong session with no error, and it is how a live period-bearing session was read as vanished and dropped from `sessions.json` with all its scrollback. Before this task the rule was carried by a naming-convention source scan that had been widened twice; the task moves it into the type system.

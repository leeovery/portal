# A Portal menu inside the tmux session

The user drives tmux almost entirely through a menu rather than its key bindings. Their config loads `jaclu/tmux-menus`, bound to Alt-M with no prefix (`@menus_trigger 'M-m'`, `@menus_without_prefix 'Yes'` in `~/.config/tmux/tmux.conf`), and it is the thing that makes tmux usable day to day: nothing has to be remembered, every action is a labelled item. The prefix itself, rebound to Ctrl-Space, is unreliable in practice ("doesn't work half the time"), so the user never uses it and everything they do reaches tmux through that menu or through Portal.

The idea is a Portal-owned menu that does the same job: a floating menu opened from a single shortcut inside any session, styled in Portal's own Modern Vivid look rather than tmux's default, offering Portal's session actions in one place. The actions the user has in mind are renaming the session, pausing a pane into the waiting state described in `2026-10-05--pause-pane-to-waiting-state.md`, sending it back to waiting, and whatever else turns out to belong there. Beyond the actions themselves, the goal is presence: today Portal is something you pass through on the way into a session, and once you are in, nothing of it is visible. A menu like this would make Portal an on-brand layer around the tmux session rather than only the picker in front of it.

The user flags that this needs discussion before anything else, because it changes what Portal is. Portal is a session manager that runs, hands the terminal to tmux and gets out of the way (apart from the background daemon); a shortcut that brings up a Portal menu from inside a running session means Portal has some presence inside the session that it does not have today. Whether and how that fits is the open question, not a detail.

Related prior material: the `lazy-resume-on-attach` discussion examined tmux's own overlay facilities — `display-menu`, the one behind the user's Alt-M menu, and `display-popup` — when deciding how to draw the resume panel, and recorded why each was rejected for that purpose (`.workflows/lazy-resume-on-attach/discussion/lazy-resume-on-attach.md`, around the section on the panel's drawing surface).

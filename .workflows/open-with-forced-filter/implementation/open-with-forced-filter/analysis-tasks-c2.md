# Analysis Tasks: Open With Forced Filter (Cycle 2)

## Task 1: Route every search surface's session set through one attached-session read
severity: medium
sources: architecture, duplication

**Problem**: "Which live sessions a search can reach" is authored three times on one feature, and one of the three answers differently.

- `cmd/completion.go:62-75` — `completeSearchTerm` walks `completionSessionNames()` (raw `ListSessionNames`, filtered only for `_`-prefixed internals and embedded slashes) and never consults the attached session. Inside tmux, `x /<TAB>` therefore offers the session the user is currently sitting in. Accepting that candidate and pressing Enter cannot attach anything — `searchCandidates` excludes the attached session from the count, and the picker's `filteredSessions` excludes it from the list — so the user lands on a picker filtered to zero rows, having just tab-completed a real session name off Portal's own list. The sigil never fails, so no message accounts for it. No test covers the gap: `cmd/completion_test.go` drives `completeSearchTerm` against a name-list seam with no notion of a current session.
- `cmd/open.go:725-731` and `cmd/open_search.go:98-111` — the *read* that produces `PickerSessions`' `currentSession` argument is written twice, byte-for-byte differently. `openTUI` does `if tmux.InsideTmux() { name, err := client.CurrentSessionName(); if err == nil && name != "" { cfg.insideTmux = true; cfg.currentSession = name } }`; `searchCandidates` does `if !tmux.InsideTmux() { return sessions }; current, err := src.CurrentSessionName(); if err != nil || current == "" { return sessions }`. If either changes its source, its tolerance of a failed or empty answer, or the `InsideTmux()` gate in front of it, `/term` starts counting over a set the picker does not list — seen as `x /term` attaching the session the user is already in (a `switch-client` to self, which reads as a keypress that did nothing), or as a picker opening on one row after the count said two. Nothing fails to compile, and no test pairs the two sites: `TestOpenCommand_SearchForm_ExcludesTheCurrentSessionFromTheCount` drives `searchCandidates` through a fake source and `TestPickerSessions` drives the helper directly.

**Solution**: Collapse the read to one function and put all three surfaces on it.

- Add one helper in `cmd`, beside `searchCandidates` — `currentPickerSession(...)` returning the attached session's name, and the empty string outside tmux and on a failed or empty read. It takes a one-method parameter (`CurrentSessionName() (string, error)`) so all three callers pass what they already hold: `openTUI`'s context client, the `SearchSessionSource` seam, and the completer's own `tmux.DefaultClient()`. Its error policy is the one the specification already fixes and `searchCandidates` already implements — a failed or empty read drops nothing, so a session is never excluded on a failed read.
- `searchCandidates` passes the helper's result straight to `tui.PickerSessions`; `openTUI` sets `cfg.insideTmux` / `cfg.currentSession` from the same call, so the title's copy of the name and the count's exclusion come from one read of one rule.
- `completeSearchTerm` calls the helper and skips that name in the loop it already runs (beside its existing embedded-slash skip). It works over a `[]string` of names rather than `[]tmux.Session`, so it cannot call `tui.PickerSessions` without changing `completionSessionNames`' shape and its test seam — settled as a skip rather than a reshaping, because what the findings show must not be re-authored is the *read* (the `InsideTmux` gate plus the error tolerance, which is where the policy and the branching live), not a compile-checked `name == current` equality. `tui.PickerSessions` remains the single declaration of the set rule for its slice-shaped consumers.
- Scope to the search completer only. `completeSessionNames`, which serves `-s` and the bare positional, is pre-existing surface where offering the current session is harmless and is not touched.
- The completer gains one tmux round trip (`CurrentSessionName`) on the bootstrap-exempt `__complete` path, which already pays one for `ListSessionNames`; a failed read costs nothing, since it drops nothing. The helper must keep degrading rather than erroring there, because completion has no channel for a failure.
- This extends cycle 1's approved Task 1 rather than reversing it: that task's "`searchCandidates` keeps its own read … the seam stays where it is" scoped what *it* changed — `tui.PickerSessions` stays the one set rule and `SearchSessionSource` is untouched here; only the read producing its argument is collapsed, and the completer, which the rule never reached at all, is brought onto it.

**Outcome**: Inside tmux, `x /<TAB>` never offers the session the user is attached to, so every candidate the completer hands back is one the sigil can actually reach. The count, the picker's list and the completer's offered set all answer from a single reading of which session that is.

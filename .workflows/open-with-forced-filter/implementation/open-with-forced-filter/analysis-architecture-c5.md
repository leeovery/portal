- FINDING: Model state a later event depends on is staged through pointer receivers that value-returning handlers must hand-sequence
  SEVERITY: medium
  FAILURE: A `portal open /term` invocation whose single match was already decided exits 0 having attached nothing, or a project pick taken during a cold-boot `portal open -- <cmd>` is silently dropped — no band, no mint, no error. The user sees a keystroke that registered visibly (the loading page lifts, or the banner swapped) and then nothing happening, with no way to tell whether the pick was taken. The mis-spelling that causes it compiles and no guard or test enumerates the call sites.
  FILES: internal/tui/model.go:1508, internal/tui/model.go:1628, internal/tui/model.go:1671, internal/tui/model.go:1823, internal/tui/model.go:1942, internal/tui/model.go:2855, internal/tui/model.go:2859, internal/tui/search_decision.go:38
  DESCRIPTION: This work added or converted four methods that mutate the model through a pointer receiver while returning only a `tea.Cmd` — `dismissLoadingGate`, `resolveSearchDecision`, `createSession` and `createSessionInCWD`. The state they write is load-bearing for a step that runs later: `resolveSearchDecision` sets `selected`/`searchAttached`/`searchErr` that `processTUIResult` reads after the program returns, and `createSession` stages `stagedMint`/`stagedMintDir` that the terminal `BootstrapCompleteMsg` reads to perform the mint. Every caller is a value-receiver handler that returns its own copy of `m`, so the mutation only survives if the caller spells it `cmd := (&m).method(...)` on its own line: Go leaves the relative order of the plain operand `m` and the mutating call unspecified in `return m, (&m).method(...)`, so the obvious one-line spelling compiles and returns the pre-mutation copy. All three call-site boundaries are currently spelled correctly, and the contract is carried by a prose warning on `createSession` plus convention — not by the compiler, a guard test, or the signature. Every other state-mutating handler in this package (`handleProjectEnter`, `handleNewInCWD`, `handleThemePanelKey`, …) is value-in/value-out, so the four newcomers are the odd shape in the package that a later edit is most likely to normalise back to the natural spelling.
  RECOMMENDATION: Give the four the shape the surrounding handlers already use — `func (m Model) dismissLoadingGate() (Model, tea.Cmd)` and the same for `resolveSearchDecision`, `createSession` and `createSessionInCWD` — so a caller reads `m, cmd := m.createSession(dir); return m, cmd` and the losing spelling (`return m, m.createSession(dir)`) fails to compile rather than silently dropping the state. The warning comment on `createSession` and the `(&m).` call-site idiom both go away with it.

- FINDING: The positional completer reads a `/word` as a search sigil after `--`, where the parser reads it as the trailing command's own argument
  SEVERITY: low
  FAILURE: `portal open ~/Code/api -- ls /po<TAB>` offers live session names (`/portal-a1b2`) for a word that `open` will hand verbatim to `ls`. The user accepts the completion and the trailing command fails on a path that does not exist; on a shell honouring `ShellCompDirectiveNoFileComp` the filenames they wanted are suppressed at the same time, so the only offer is the wrong one.
  FILES: cmd/completion.go:84, cmd/open.go:785, cmd/open_search.go:14
  DESCRIPTION: Recognition of the search form is deliberately bounded by the `--` separator on the parse side: `searchFormPositionals` scans only `preDashPositionals`, so a `/word` among a trailing command's own arguments is never a sigil. `completeOpenPositional` restates the recognition rule without that bound — it is registered as `func(_ *cobra.Command, _ []string, toComplete string)`, discarding both the command (whose `ArgsLenAtDash()` cobra has already populated by the time `ValidArgsFunction` runs) and the preceding positionals, and dispatches on `resolver.IsSearchSigil(toComplete)` alone. The two surfaces this work touched therefore disagree about the same word: what the completer offers a sigil completion for is something the parser will not treat as a sigil. Verified against the built binary — cobra does invoke `ValidArgsFunction` for a post-`--` word (`portal __complete open -- ls /po` answers with `ShellCompDirectiveNoFileComp`, which only this function returns).
  RECOMMENDATION: Take the command and args cobra already supplies and gate the sigil arm on the same boundary the parser uses, so the completer and `searchFormPositionals` answer "is this word a sigil?" from one rule rather than two.

SUMMARY: The feature composes cleanly at its main seams — the match rule, the searched set and the home-abbreviated display form each have a single home that `cmd`, `internal/tui` and the completer all route through, and the recorded-versus-derived directory split is carried by a genuine second field rather than by discipline. The two findings are a family of pointer-receiver staging methods whose correctness rests on how each caller spells the call rather than on the signature, and a completer that restates the sigil recognition rule without the `--` boundary the parser applies.

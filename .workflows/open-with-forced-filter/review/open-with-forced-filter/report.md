# Implementation Review: Open With Forced Filter

**Plan**: open-with-forced-filter
**Verdict**: Pass

## Summary

This is the third review cycle. The second sent one item back to planning — the containment filter's cross-generation borrowing of a colliding target's verdict — which became phase 14's single task. That task is verified here and is delivered: `set` (`internal/tui/search_filter.go:40-61`) now accumulates every distinct field pair any generation of the list has produced for a filter value, under one write hold with each held slice cloned rather than shared, so a filter pass running behind a list rebuild finds both colliding sessions' pairs under the one key, they disagree, and every row behind that target is withheld. The ranking rule, `current`, `everyEntryMatches`, `installSearchFilter` and both `FilterValue()` methods are unedited; the two doc comments that previously asserted an unqualified guarantee the code did not hold now state the rule it does. The four new cross-generation tests fail under the pre-change implementation, so they are pins rather than tautologies.

Five change-set verifiers held the whole change-set against §1–§4, §5–§8, §9–§10, §11 and the test surface, each executing what the project's conventions allow. All five returned zero findings, as did the task verifier. No finding was collected in this cycle, so nothing was assessed, applied or routed.

**This cycle was measured rather than only read.** `go build ./...`, `gofmt -l .`, `go vet ./...`, `go vet -tags integration ./...` and `golangci-lint run ./...` are clean over the whole tree (the lint config sets the `integration` tag, so the tagged files type-check too). The whole unit lane — `go test ./...`, 40 packages — is green, which closes the repeated "`go test ./...` passes" criterion for every task that carried it, including the packages the change-set never touched. `go test -race ./internal/tui` is green over the containment filter, including the concurrent-`set` test. The emitted `portal init bash` and `portal init zsh` shims were driven through real bash 5.3.15 and zsh over a recording stub and ask Portal for `open`'s completions. The README and both help texts were rendered and checked against what §9.2 obliges, and the two committed capture frames were read as images at the tape's own 105×27 geometry, carrying all five directory-column branches.

Five mutation probes, driven in a disposable copy of the tree under the session scratchpad and torn down afterwards, confirm the load-bearing guards are not vacuous: widening the sessions-page key guard to swallow `s` under an applied filter reddens the directory-column and capture-fixture suites (which settles task 3-5's own gated experiment); deleting the source's mutex reddens the race test under `-race`; no-opping `installSearchFilter` reddens thirteen containment subtests; turning `everyEntryMatches` into an any-entry test reddens the collision carve-out including the since-departed-collider residual; and deleting the `--` bound from `completeOpenPositional` reddens three separator-bound subtests. The repository tree was never modified — `git status --porcelain` is identical across the pass.

What remains unmeasured is the integration lane and what only it or a different machine can reach: the eight live cold-boot observations of task 4-5, the live-paint half of the cold classification, the end-to-end warm attach with the saver down (which the project's own absolute invariant forbids signalling), the fish completion leg (fish is not installed), the `bash-completion` cursor measurement task 5-5's shim edit was gated on (the package is absent), and the human visual-gate record. Each is named below with the command or condition that settles it.

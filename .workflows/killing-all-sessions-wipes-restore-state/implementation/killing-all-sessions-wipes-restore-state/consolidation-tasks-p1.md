# Consolidation Tasks: Killing All Sessions Wipes Restore State (Phase 1)

## Task 1: Every Capture Read Refused By An Exiting Tmux Logs As A Back-Off
placement: phase 1
severity: behaviour

**Problem**: Only two of the commit cycle's tmux read failures are classed as "tmux stopped answering": the session listing (`internal/state/capture.go:94`) and the confirmation (`internal/state/scrollback.go:355`). An exiting tmux refuses whichever read lands after its exit begins, and the cycle's skeleton-marker read (`ListSkeletonMarkers`, `internal/state/scrollback.go:345-348`, returned as a plain `list skeleton markers: %w`) and pane listing (`ListAllPanesWithFormat`, `internal/state/capture.go:101-104`) come back unwrapped. `cycleFailureMessage` (`cmd/state_daemon.go:244-249`) classifies on the sentinel alone for all three committers — the tick (`cmd/state_daemon.go:204`), the final flush (`cmd/state_daemon.go:391`) and `failCommitNow` (`cmd/state_commit_now.go:152`) — so a shutdown landing on either read logs `tick failed`, `final flush failed` or `commit cycle failed`, the words used for a genuine fault such as a parse error or `errCarryNameTaken`. A reboot log grepped for back-off lines undercounts the saves that were in flight as tmux went down, and the matching "failed" lines read as real faults. Today's classification is pinned in two places beyond the marker-read tests the Solution names: `cmd/state_daemon_save_request_test.go:97` expects `tick failed` for a failed pane listing, and `TestRunCommitCycleDoesNotClassifyAFailedMarkerReadAsTmuxStoppedAnswering` (`internal/state/commit_cycle_confirm_test.go:423-446`) asserts that a failed skeleton-marker read is left unclassified.
**Solution**: Wrap the tmux-read failures of the skeleton-marker read and the pane listing in `state.ErrTmuxStoppedAnswering`, the same way the session listing is wrapped, so every capture read tmux refuses logs through the existing back-off line. Non-read failures stay "failed": `parsePaneRows`, `errCarryNameTaken` and the all-sessions-anomalous aggregate. Widen the sentinel's doc to cover a refused capture read as well as a refused confirmation, and move the expected message of the marker-read tests (`cmd/state_daemon_run_test.go:705` and `:765`) to the back-off line. Writes, retries, `save.requested` and `flush_completed` do not change; only the logged message moves. Settled by spec §4.2, which asks for a back-off line whenever a committer backs off because tmux stopped answering mid-save — a refused read anywhere in the capture is that case.

**Outcome**: Every capture read an exiting tmux refuses — the skeleton markers, the session listing, the pane listing and the confirmation — ends the tick, the shutdown flush and `commit-now` with that committer's back-off line, carrying tmux's own words in `error`. A failure that is not a refused read still logs `… failed`, and nothing a failed cycle writes, retries or reports changes beyond the message.

**Acceptance Criteria**:
- [ ] With a saved `sessions.json` and its scrollback files on disk, tmux refuses the skeleton-marker read during the daemon's tick, during its shutdown flush and during `commit-now`. Each logs its back-off line — `tick backed off: tmux stopped answering`, `final flush backed off: tmux stopped answering`, `commit cycle backed off: tmux stopped answering` — at INFO or above with tmux's own words in `error` and no `… failed` line beside it. No session listing is read, and `sessions.json` and every scrollback file are unchanged. (§2.5, §4.2, §6.3)
- [ ] With the same saved state, the session listing names a live session and tmux then refuses the pane listing, during the tick, during the shutdown flush and during `commit-now`. Each logs its back-off line with tmux's own words in `error` and no `… failed` line beside it, and `sessions.json` and every scrollback file are unchanged. (§2.5, §4.2, §6.3)
- [ ] After either refusal, the tick leaves `save.requested` present and its next tick, with every read answered, commits; `commit-now` touches `save.requested` and exits non-zero; the shutdown flush's `shutdown` line reports `flush_completed=false`. (§2.5)
- [ ] A committing cycle whose skeleton-marker read or pane listing tmux refuses returns an error matching `state.ErrTmuxStoppedAnswering` from which the read's own error is still reachable. (§4.2)
- [ ] A tick whose pane listing is answered but fails to parse, one whose waiting pane's session is carried onto a name a captured session holds, and one in which every session's environment read fails anomalously each log `tick failed` and no back-off line. (§4.2)
- [ ] The restore-in-progress marker read fails in the tick, in the shutdown flush and in `commit-now`. Each logs its existing line for that failure, unchanged, and no back-off line. (§4.2)

**Do**:
- Wrap the `ListSkeletonMarkers` failure in `captureAndRefile` (`internal/state/scrollback.go:345-348`) and the `ListAllPanesWithFormat` failure in `captureStructure` (`internal/state/capture.go:101-104`) in `ErrTmuxStoppedAnswering`, the way `internal/state/capture.go:94` wraps the session listing, so the read's own error stays reachable.
- Leave unwrapped the `parsePaneRows` failure (`internal/state/capture.go:105-108`), `errCarryNameTaken` and the all-sessions-anomalous aggregate (`internal/state/capture.go:135-140`). `cycleFailureMessage` and the three committers' failure routes do not change.
- Widen the `ErrTmuxStoppedAnswering` doc (`internal/state/scrollback.go:245-247`), which today names only a failed session listing and a refused confirmation, to cover a failed capture read as well as a refused confirmation.
- Move every test that pins today's classification of these two reads. `rg -n '"tick failed"|"final flush failed"|"commit cycle failed"|DoesNotClassifyAFailedMarkerRead' cmd internal/state -g '*_test.go'` → 12 hits. Four are driven by a skeleton-marker or pane-listing failure and move: `cmd/state_daemon_run_test.go:705` and `:765` (marker read) and `cmd/state_daemon_save_request_test.go:97` (pane listing, whose subject is the failed `save.requested` re-raise, so only its expected cycle line moves) go to `tick backed off: tmux stopped answering`, and `TestRunCommitCycleDoesNotClassifyAFailedMarkerReadAsTmuxStoppedAnswering` (`internal/state/commit_cycle_confirm_test.go:423`) asserts the opposite of this task. The other eight — the back-off suite's absence checks, a failed `sessions.json` write, a carry collision, a held commit lock and a test comment — stay as they are.

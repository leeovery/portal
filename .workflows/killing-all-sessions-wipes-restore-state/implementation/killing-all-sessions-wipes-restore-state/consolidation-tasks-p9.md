# Consolidation Tasks: Killing All Sessions Wipes Restore State (Phase 9)

## Task 1: A Deferred Pane's Capture Is Written Once The Commit That Frees Its Name Has Landed
placement: phase 9
severity: behaviour

**Problem**: The contested-name guard defers the write of a contested pane that has no usable token (no token, or one `PendingScrollbackPath` refuses): `writeUnderToken` returns `(false, nil)` (`internal/state/commit_cycle.go:118-122`) and the capture is dropped. That is right when the cycle ends uncommitted. When the cycle commits, the deferred pane's fresh record names its positional file, which still holds the bytes of the tokened pane whose committed record contested it — that pane's record moves onto its token-named link of the same inode in the same commit. If the deferred pane was itself moved, that commit's housekeeping (`gcOrphanScrollback` in `commitOver`, `internal/state/commit.go:56`) deletes its previous file, because no record names it any more. Until the next committing dump cycle (the next `save.requested` touch or up to 30s, `MaxGap`), `sessions.json` names a neighbour's transcript on the deferred pane and the pane's own transcript is on no file. If tmux goes down in that window — a reboot whose shutdown flush stands down — the next restore replays the neighbour's history into that pane and its own is gone. A realistic trigger is `renumber-windows on` and closing a window ahead of a hook-less pane created after restore, with a tokened window between them; a brand-new hook-less pane opened at a vacated index before the next commit hits it the same way. The consolidation finder measured it with an overlay probe: on HEAD the tokenless pane A (saved at `work:3.0`, live at `work:2.0`) is committed naming `work__2.0.bin` holding tokened B's saved bytes, with `work__3.0.bin` deleted; on the pre-phase tree (`3b67f0809~1`) A's committed record holds A's capture. Three tests now assert the contaminated committed state: `internal/state/commit_cycle_shifted_test.go:229-236` (the "in the same cycle" row), `internal/state/commit_cycle_contested_test.go:259-262`, and `cmd/state_daemon_run_test.go:640-655` with `:635`.

**Solution**: Keep each deferred capture and write it at its positional name once this cycle's `sessions.json` write has landed, inside the same locked cycle. This revises the phase's settled direction that a deferred pane is not written that cycle, on two grounds: the measured regression above against the pre-phase tree, and §5.2's bound that a hook-less moved pane's loss lasts only until its next save completes, which the deferral breaks (and §2.3's purpose, that the next restore finds a pane's transcript at the path its record names, which a record naming a neighbour's bytes breaks for the new-pane case). The uncommitted-end guarantee the phase bought stays: a cycle whose commit does not land writes no deferred capture.
- `ScrollbackWriter` keeps each deferred pane's capture and hash instead of dropping it. `confirmEmptyCapture` runs on it at dump time as for any write, so an unconfirmed empty capture is still refused and never kept.
- `commitOver` reports whether it actually wrote `sessions.json`; today it returns nil without writing when nothing changed.
- When `sessions.json` was written, `RunCommitCycle` writes each kept capture at its positional name through `WriteScrollbackIfChanged`, updating its dedup entry. It skips any name the index it has just committed still names on a record carrying another pane's token — a contesting record that did not move, such as after a failed skeleton link — leaving that pane deferred as today.
- The committed record then names the pane's own capture. The exposure shrinks to the moment between the `sessions.json` rename and that write, a window of the daemon's own file operations with no tmux read in it — chosen over the cheaper fallback of re-touching `save.requested` on a deferral, which only bounds the window to a tick and leaves the reboot case open.
- Spec: with this fix §5.2 stands as written — the finder's S1 is the code being wrong, not the specification, so no corrigendum is owed.
- Tests: the three sites above move to assert that, after the cycle commits, the deferred pane's record holds its own capture and the contesting tokened pane's record names its token-named transcript holding its saved bytes. Add a case for a moved tokenless pane whose previous file that commit collects, asserting its record holds its own capture. Keep the uncommitted-end assertions (failed dump, failed `sessions.json` write, the daemon's cancelled tick with a stood-down flush): no deferred capture is written and the contested positional file still holds the contesting pane's saved transcript. Cover a cycle whose `commitOver` skips the write: no deferred capture is written.

**Outcome**: The first committing cycle after a move leaves every pane's record — tokened or not, moved or new — naming a file holding that pane's own transcript, and an uncommitted end still leaves every committed record's file as it was. The one exception is a pane whose contested name the committed index still names on another pane's tokened record; that pane stays deferred as it is today.

**Acceptance Criteria**:
- [ ] Take a tokenless pane moved onto an address whose positional file the committed index names on a tokened neighbour's record: tokenless A is saved at `work:3.0` and live at `work:2.0`, and tokened B is saved at `work:2.0` and live at `work:1.0`. Once the cycle commits, A's record names `scrollback/work__2.0.bin` holding A's capture. B's record names a file holding B's own transcript: B's capture where it was written, otherwise B's saved bytes under its token-named transcript. That commit's housekeeping removes A's previous `work__3.0.bin`. The daemon's first tick over the same renumbered restore, with B skeleton-marked, leaves `work__2.0.bin` holding A's capture and B's token-named transcript holding B's saved bytes.
- [ ] Take a new pane opened at an address a tokened pane vacated, where the tokened pane's committed record still names that address. The new pane carries no token, or one the pane-token rule refuses. Once the cycle commits, the new pane's record names its positional file holding its own capture. Its dedup entry is unchanged through the dump and describes that capture once the cycle ends. The tokened pane's record names its token-named transcript holding its saved bytes.
- [ ] A cycle that defers a capture and then ends uncommitted writes no deferred capture. This covers a failed dump, a failed `sessions.json` write, and a daemon tick cancelled mid-dump followed by a shutdown flush that stands down. In each case `sessions.json` is unchanged and the contested positional file still holds the contesting pane's saved transcript.
- [ ] A committing cycle that defers a capture but skips the `sessions.json` write because nothing changed writes no deferred capture.
- [ ] A deferred pane is not written when the index just committed still names its contested name on a record carrying another pane's token. This happens when the contesting pane's skeleton link onto its token failed, which leaves its record on that file. The file still holds the contesting pane's saved transcript.
- [ ] A deferred pane's empty capture over the contested file, when the committer's own tmux server does not confirm it, is refused at dump time with an error wrapping `ErrUnconfirmedEmptyCapture`. The committing cycle writes nothing at that pane's positional name.

**Do**:
- `internal/state/commit_cycle.go`, `ScrollbackWriter` (`:60-77`): the contested branch of `Write` (`:96-98`) and `writeUnderToken`'s refusal (`:118-122`) keep a pane's capture and hash when the pane has no usable token, instead of dropping them. Before keeping a capture, run `confirmEmptyCapture` on it against `savedTranscript` as for any write. The pane's dedup entry stays as it is until the capture is written.
- `internal/state/commit.go`: `commitOver` (`:35-61`) reports whether it wrote `sessions.json`. Its return when nothing changed is at `:44-46`. `Commit` (`:28-31`) is its only other caller.
- `RunCommitCycle` (`internal/state/commit_cycle.go:157-198`): when `commitOver` reports the write, write each kept capture at its positional name through `WriteScrollbackIfChanged` and update its dedup entry, inside the same locked cycle. Skip any name that the index just committed names on a record carrying another pane's token. Write no kept capture when the dump fails or when the `sessions.json` write fails or is skipped.
- These test sites assert the contaminated committed state and move:
  - `internal/state/commit_cycle_shifted_test.go:229-236`, the "in the same cycle" row.
  - `internal/state/commit_cycle_contested_test.go:259-262`. Its follow-on cycle at `:266-274` expects the same capture to be written again, because the first cycle left it unwritten.
  - `cmd/state_daemon_run_test.go:640-655` with `:635`.
- These uncommitted-end assertions stay: `internal/state/commit_cycle_contested_test.go:276-289` and `internal/state/commit_cycle_shifted_test.go:244-299`. The existing cancelled-tick-then-stood-down-flush test, `cmd/state_daemon_contested_test.go:47-113`, covers only a tokened contested pane.

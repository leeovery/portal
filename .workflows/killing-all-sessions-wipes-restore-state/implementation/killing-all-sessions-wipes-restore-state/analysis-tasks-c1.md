# Analysis Tasks: Killing All Sessions Wipes Restore State (Cycle 1)

## Task 1: The Commit Cycle Owns The Empty-Capture Confirmation Of Every Scrollback Write
severity: medium
sources: architecture

**Problem**: The capture confirmation is enforced inside `RunCommitCycle`. `captureAndRefile` is unexported, and the cycle carries its own `Client` and `OwnServer`. The scrollback half of the same rule is enforced only by the caller. The cycle hands its `Dump` a bare `CaptureCycle` (`internal/state/commit_cycle.go:46`), so the daemon's `dumpPane` (`cmd/state_daemon.go:331-352`) makes three exported calls in order and passes the confirmer, own-server pid, state dir and hash map again from `daemonDeps`: `state.CaptureAndHashPane`, `state.ConfirmEmptyCapture` (`internal/state/scrollback.go:285`), then `state.WriteScrollbackIfChanged` (`internal/state/scrollback.go:77`). `WriteScrollbackIfChanged` writes whatever it is handed. A second dumper, or a rework that reorders or merges the daemon's write, could write tmux's shutdown answer to `capture-pane` (exit 0, no output) over a live session's saved transcript. Nothing would stop it: no compile error and no guard. The user finds the restored pane blank after the reboot, and the bytes are gone. The save path's other irreversible write is already guarded structurally: `state.Commit` is reachable from production only through `RunCommitCycle`, and `internal/state/commit_guard_test.go` pins that.
**Solution**: `RunCommitCycle` hands the `Dump` a scrollback writer bound to the cycle's own `Client`, `OwnServer`, `Dir` and `HashMap`. For example, the dump becomes `func(CaptureCycle, ScrollbackWriter) (bool, error)`, where `Write(paneKey, data, hash)` runs the empty-capture confirmation before the dedup write. A refused write returns an error wrapping `ErrUnconfirmedEmptyCapture`. `ConfirmEmptyCapture` becomes unexported. `WriteScrollbackIfChanged` stays exported for test fixtures only. The commit guard's scan is extended to fail any non-test file outside `internal/state` that names it, the same way it refuses `state.Commit`. The daemon's `dumpPane` then makes one write call and no longer passes `OwnServer`, `Dir` or `HashMap` itself. It keeps its two existing WARN lines, `empty capture not confirmed; saved transcript kept` (the refusal line §4.2 requires) and `write scrollback failed`, and tells them apart with `errors.Is` against `ErrUnconfirmedEmptyCapture`. Behaviour is unchanged: the writes, refusals, tallies and log lines are the same, and only the place the rule lives moves. This direction follows the record: it is the finding's recommendation, and it matches the structural precedent the commit guard sets for `state.Commit`.
**Outcome**: The only route from production code to a saved scrollback file runs through a writer that has already applied the empty-capture rule. A production file outside `internal/state` that names `WriteScrollbackIfChanged` fails the unit-lane guard.

**Acceptance Criteria**:
- [ ] A live pane has a saved non-empty transcript, and its capture comes back empty. The read sent after that capture is refused, answered by another server on the socket, or answered naming no server. The daemon's tick and its shutdown flush each leave the transcript unchanged. Each logs one `empty capture not confirmed; saved transcript kept` line at WARN carrying `pane_key` and `error`. (§2.4, §4.2, §6.1, §6.3)
- [ ] With the same saved transcript and the committer's own server answering the read sent after the empty capture, the tick and the flush each write the empty capture and log no refusal line. Each sends exactly one confirmation read for that capture, beside the cycle's own. (§2.4)
- [ ] A daemon scrollback write that fails for any other reason logs `write scrollback failed` with `pane_key` and `error`, and no refusal line. A refused write and a failed write each still count once in the `tick complete` line's `anomalous` tally. (§4.2)
- [ ] Through the writer the commit cycle hands its dump, three captures are written without sending a confirmation read: a non-empty capture over a saved transcript, an empty capture with no saved transcript, and an empty capture over an empty saved transcript. A capture matching the cycle's dedup entry writes nothing and reports no change. (§2.4)
- [ ] Through the same writer, an empty capture over a saved transcript that cannot be inspected, whose confirmation another server answers, writes nothing. It returns an error matching `state.ErrUnconfirmedEmptyCapture`, with `state.ErrNotOwnServer` reachable from it. (§2.4)
- [ ] A non-test file outside `internal/state` that names `state.WriteScrollbackIfChanged` fails the unit-lane guard, whether it calls the function or takes it as a value under an import alias. Test files anywhere, files inside `internal/state`, and a selector of that name on another package are not findings. The guard reports nothing over the current tree. (§2.4)

**Do**:
- `internal/state/commit_cycle.go`: `CommitCycle.Dump` (`:46`) receives a scrollback writer beside the `CaptureCycle`. `RunCommitCycle` (`:56-77`) binds the writer to the cycle's own `Client`, `OwnServer`, `Dir` and `HashMap`. Its write runs the empty-capture confirmation before the dedup write, and a refusal returns an error wrapping `ErrUnconfirmedEmptyCapture`.
- `internal/state/scrollback.go`: unexport `ConfirmEmptyCapture` (`:279-293`). `WriteScrollbackIfChanged` (`:75-87`) stays exported, for test fixtures only.
- `cmd/state_daemon.go`: in `scrollbackDump.dumpPane` (`:327-354`), the `state.ConfirmEmptyCapture` call (`:342`) and the `state.WriteScrollbackIfChanged` call (`:347`) become one write through the writer `run` (`:303`) receives. `dumpPane` passes no `OwnServer`, `Dir` or `HashMap` of its own. Its two WARN lines and its `anomalous` tally stay as they are, told apart with `errors.Is` against `state.ErrUnconfirmedEmptyCapture`.
- Only the daemon calls these functions in production: `rg -n 'WriteScrollbackIfChanged|ConfirmEmptyCapture' --type go -g '!*_test.go'` → 6 hits. Four are the two declarations and their doc lines in `internal/state/scrollback.go` (`:75`, `:77`, `:279`, `:285`). The other two are the daemon's calls (`cmd/state_daemon.go:342`, `:347`), and both convert.
- Every `Dump` takes the new shape: `rg -n 'Dump:|cycle\.Dump\b' --type go` → 18 hits across 7 files. They are the cycle itself (`internal/state/commit_cycle.go:68-69`), the daemon (`cmd/state_daemon.go:273`) and the test fixtures in `cmd/state_commit_now_test.go` (the stand-in `RunCommitCycle`, `:102-104`), `internal/state/commit_cycle_test.go`, `internal/state/commit_cycle_uncommitted_test.go`, `internal/state/capture_carry_test.go` and `internal/restore/lazy_resume_panel_integration_test.go`.
- `internal/state/empty_capture_test.go` calls `state.ConfirmEmptyCapture` directly (`:52`, `:72`). Once the function is unexported, its scenarios reach the rule through the cycle's writer.
- `internal/state/commit_guard_test.go`: the scan that refuses `state.Commit` (`scanForDirectCommit`, `namesStateCommit`) also refuses `WriteScrollbackIfChanged`, with rule cases in the shape of `TestCommitGuard_Rule`'s.

## Task 2: A Capture That Fails Because Tmux Stopped Answering Logs As A Back-Off Whichever Read Failed
severity: low
sources: architecture

**Problem**: A capture read is classed as a back-off only if its failure is wrapped at one of the chosen sites. Today those are the skeleton-marker read, the session listing, the pane listing and the confirmation (`internal/state/scrollback.go:345-348`, `internal/state/capture.go:94` and `:103`, `internal/state/scrollback.go:356`). The per-session `show-environment` reads (`internal/state/capture.go:115-127`) are not on that list. Sometimes tmux begins exiting after the pane listing and before any environment read has succeeded. Its refusals ("server exited unexpectedly", "no server running") are not no-such-session, so every read lands in `anomalousErrs`. `captureStructure` then returns the unwrapped `capture: all N sessions failed` aggregate (`internal/state/capture.go:135-140`). `captureAndRefile` returns it before sending the confirmation (`internal/state/scrollback.go:350-353`), so the one authoritative read is never consulted. `cycleFailureMessage` (`cmd/state_daemon.go:244-249`) then logs `tick failed`, `final flush failed` or `commit cycle failed` where §4.2 asks for the back-off line. A reboot log grepped for back-off lines (§4.3) misses that save, which was in flight as tmux went down, and shows it as a genuine fault instead. Any capture read added later would have the same gap.
**Solution**: In `captureAndRefile`, when `captureStructure` fails with an error that does not already match `ErrTmuxStoppedAnswering`, send the own-server confirmation before returning. If the confirmation is refused (the read fails, the answer is silent, or another server answers), wrap the capture's error in `ErrTmuxStoppedAnswering` so both the capture's error and the confirmation's cause stay reachable. If the committer's own server answers, return the capture's error unchanged, so it still logs `… failed`. If the own server is unknown, no confirmation is sent and the error also stays unchanged: an unsent read proves nothing about whether tmux answered. This carries the approved phase 1 consolidation's principle further (a refused read anywhere in the capture is a back-off, settled by §4.2) and keeps its line. On a healthy server, a parse failure, a carry collision onto a captured session's name, and every environment read failing anomalously all get an answered confirmation and still log `tick failed`, so that task's tests hold as they are. Widen the `ErrTmuxStoppedAnswering` and `captureAndRefile` docs to say a capture failure is classified by the confirmation. Writes, retries, `save.requested` and `flush_completed` do not change; only the logged message moves.
**Outcome**: When every environment read is refused by an exiting tmux, the tick, the shutdown flush and `commit-now` each log their back-off line with tmux's own words in `error`, and they write nothing.

**Acceptance Criteria**:
- [ ] A saved `sessions.json` and its scrollback files are on disk. The session and pane listings name a live session. tmux then refuses every session's environment read ("server exited unexpectedly") and the confirmation sent after them. This happens during the daemon's tick, during its shutdown flush and during `commit-now`. Each logs its back-off line at INFO or above, with tmux's own words in `error` and no `… failed` line beside it: `tick backed off: tmux stopped answering`, `final flush backed off: tmux stopped answering` or `commit cycle backed off: tmux stopped answering`. `sessions.json` and every scrollback file are unchanged. (§2.5, §4.2, §6.3)
- [ ] After that back-off, the tick leaves `save.requested` present, and its next tick commits once every read is answered. `commit-now` touches `save.requested` and exits non-zero. The shutdown flush's `shutdown` line reports `flush_completed=false`. (§2.5)
- [ ] A committing cycle's capture fails on something not already classed as a refused read. Its confirmation is then refused, answered naming no server, or answered by another server. The cycle returns an error matching `state.ErrTmuxStoppedAnswering`, and both the capture's error and the confirmation's cause are reachable from it. (§2.2, §4.2)
- [ ] With the committer's own server answering the confirmation, three ticks each log `tick failed` and no back-off line: one whose pane listing fails to parse, one whose waiting pane's session is carried onto a name a captured session holds, and one in which every session's environment read fails anomalously. (§4.2)
- [ ] A committing cycle whose own server is unknown, and whose capture fails, sends no confirmation read. It returns the capture's error unchanged. (§2.2)
- [ ] When tmux refuses a capture's session listing or pane listing, the cycle ends at that read and sends no confirmation after it. (§4.2)

**Do**:
- `internal/state/scrollback.go`: `captureAndRefile` (`:346-365`) adds the own-server confirmation to its failed-capture return (`:351-355`), as the Solution sets out. The existing own-server check (`confirmOwnServer`, `:261-273`) refuses an unknown own server without sending a read. On this path that case leaves the capture's error unwrapped.
- Leave these unchanged: a capture error that already matches `ErrTmuxStoppedAnswering` (the session listing at `internal/state/capture.go:92-95`, the pane listing at `:101-104`), `cycleFailureMessage` (`cmd/state_daemon.go:244-249`), and the three committers' failure routes (`cmd/state_daemon.go:204`, `:391`, `cmd/state_commit_now.go:152`).
- The `ErrTmuxStoppedAnswering` doc (`internal/state/scrollback.go:245-248`) today lists the reads it covers. The `captureAndRefile` doc (`:334-345`) today says a failed capture returns the error the capture gave. Widen both as the Solution says.
- These tests pin today's classification and stay as they are. `TestDaemonTickReportsAFailureThatIsNoRefusedReadAsFailed` (`cmd/state_commit_backoff_test.go:374-416`): its fake answers the confirmation as the own server. `TestRunCommitCycleClassifiesARefusedCaptureReadAsTmuxStoppedAnswering` (`internal/state/commit_cycle_confirm_test.go:423-454`): it asserts the refused read is the cycle's last.

## Task 3: CLAUDE.md Describes The Save Path And Resume Shells As They Were Before This Fix
severity: drift
sources: architecture

**Problem**: CLAUDE.md is the architecture reference agents are told to defer to. It contradicts the landed save path in four places.
- The `state` row (`CLAUDE.md:61`) has the waiting pane's re-file vacate its positional path. It says nothing of the own-server confirmation sent after the last capture read, the committing path's `ListSessionNamesProbe` listing, the `ErrTmuxStoppedAnswering` stand-down class, or the dump's refusal of an unconfirmed empty capture.
- The `tmux` row omits `ConfirmAnswering`, `ListSessionNamesProbe` and `ServerPIDFromEnv`.
- The Resume hooks section (`CLAUDE.md:192`) quotes the eager shell as `sh -c '<HOOK>; exec $SHELL'` and the parked chain as `trap : INT QUIT` running the draw once. It does not mention the draw or the waiter catching SIGTERM.
- `CLAUDE.md:194` says the re-file is a no-replace rename through `internal/state/rename_noreplace_{darwin,linux}.go`, and both files are deleted.

An agent that brings the code back in line with this text could restore the move, or add a committer or capture read without the confirmation, or drop the TERM handling. Any of those reopens the uncommitted-cycle and shutdown-wipe holes, and the result shows only as sessions and scrollback lost at a later reboot. No test reads CLAUDE.md.
**Solution**: Update CLAUDE.md in those four places to state what holds.
- **`state` row.** The re-file is a hard link (`link(2)`) that never overwrites an existing token-named file and leaves the positional name for the housekeeping pass of a commit naming the token-named path. Every committing cycle stands down unless the committer's own tmux server answers a confirmation sent after the last capture read. The committing path lists sessions through `ListSessionNamesProbe`, while the shared listing keeps its "no server, no sessions" reading. `ErrTmuxStoppedAnswering` is the stand-down class the back-off lines key on. An empty capture over a saved transcript is written only once the own server confirms it.
- **`tmux` row.** Add `ConfirmAnswering`, `ListSessionNamesProbe` and `ServerPIDFromEnv`.
- **Resume hooks section.** The hook shell runs `trap : TERM; <HOOK>; exec $SHELL` (`hookShellTrap`), and the parked chain traps `INT QUIT TERM` (`parkedChainTrap`). The chain re-runs the draw while the draw ends on SIGTERM and the pane's marker still reads pending (`parkedChainDraw`). The draw and the waiter catch SIGTERM (`catchSIGTERM`). Every one of these is a caught trap, never an ignore, and SIGHUP stays uncaught.
- **`CLAUDE.md:194`.** Delete the `rename_noreplace` sentence.

The wording states the rules, not which function calls which, so it holds whether or not Tasks 1 and 2 land.

**Outcome**: CLAUDE.md describes the save path as the tree holds it: the own-server confirmation, the committing path's listing, the stand-down class, the empty-capture rule and the link-based re-file. It describes the resume shells' SIGTERM handling the same way, and it names no deleted file.

**Acceptance Criteria**:
- [ ] CLAUDE.md's `state` row describes the waiting pane's re-file as a hard link (`link(2)`) that never overwrites an existing token-named file. It leaves the positional name for the housekeeping pass of a commit naming the token-named path, and the row no longer speaks of a vacated positional path. (§2.3)
- [ ] The `state` row states four rules. Every committing cycle stands down unless the committer's own tmux server answers a confirmation sent after the last capture read. The committing path lists sessions through `ListSessionNamesProbe`, while the shared listing keeps its "no server, no sessions" reading. `ErrTmuxStoppedAnswering` is the stand-down class the back-off lines key on. An empty capture over a saved transcript is written only once the own server confirms it. (§2.1, §2.2, §2.4, §2.5, §4.2)
- [ ] The `tmux` row names `ConfirmAnswering`, `ListSessionNamesProbe` and `ServerPIDFromEnv`. (§2.1, §2.2)
- [ ] The Resume hooks section quotes the eager shell as `trap : TERM; <HOOK>; exec $SHELL` and the parked chain's trap as `INT QUIT TERM`. It states that the chain re-runs the draw while the draw ends on SIGTERM and the pane's marker still reads pending. It states that the draw and the waiter catch SIGTERM, that each of these is a caught trap and never an ignore, and that SIGHUP stays uncaught. (§3.1, §3.2, §3.3)

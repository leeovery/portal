- FINDING: An answer naming no server is refused only by the unknown-own-server guard, because both are encoded as pid 0
  SEVERITY: low
  FAILURE: confirmOwnServer refuses tmux's exit-0, no-output shutdown answer by comparing it (pid 0) with the committer's own server. For a committer whose own server is also 0 (TMUX absent or unparseable, where ownTmuxServer returns 0), the early `ownServer <= 0` return is the only thing standing between that answer and a confirmation. Next to `answered != ownServer` the guard looks redundant, since no real server has pid 0. Removing it leaves every test green: TestRunCommitCycleStandsDownWithNoOwnServer and TestCommitNowStandsDownOutsideAnyTmuxServer both use fakes that answer a non-zero pid, so they are refused on the mismatch either way. Without the guard, such a committer reads tmux's shutdown answer as its own server confirming. It then commits a capture taken during the exit: the empty index and the housekeeping wipe this fix exists to stop. Nothing shows it until the next restore brings nothing back.
  FILES: internal/state/scrollback.go:266-276, internal/state/scrollback.go:243-246, internal/tmux/tmux.go:92-99, cmd/state_commit_now.go:136-139
  DESCRIPTION: The confirmation's "a server must be named" rule is not stated anywhere in its own logic. It holds only because two different sentinels share one value: AnsweringConfirmer's "0 for an answer naming none" and CommitCycle.OwnServer's "zero stands every cycle down". Two "no server" values compare equal, so the comparison would confirm them unless something outside it intervenes. The corrigendum's property, that an empty answer never confirms, therefore rests on a separate guard written for a different case, and no test pins that guard for the pairing that matters.
  RECOMMENDATION: Make an answer naming no server a refusal in its own right. Either have confirmOwnServer refuse `answered <= 0` with ErrNotOwnServer before the comparison, or have ConfirmAnswering return that answer as an error instead of pid 0 (and update the AnsweringConfirmer contract to match). Either way the comparison only ever sees real pids, and the unknown-own-server guard becomes a second check rather than the only one. Give the no-own-server test a fake that answers naming no server, so the pairing is pinned.

# Consolidation Findings: killing-all-sessions-wipes-restore-state (Phase 8)

## Findings

### F1: The daemon still reports an unreadable sessions.json from its startup read, beside the cycle's report
- **Class**: behaviour
- **Failure**: The phase moved the report of an unreadable sessions.json into the commit cycle, at the read every committer acts on, and deleted commit-now's own pre-cycle report (`loadPrevIndex`) to match. The daemon's matching report stayed: the WARN on its startup read of the same file. A corrupt sessions.json now writes two `daemon:` WARN lines to portal.log for one condition. `ReadIndex failed` comes when the daemon starts, then `read sessions.json failed; committing without the saved index` on its first capture tick, and both carry the same cause in `error`. Someone reading the log after a boot (the post-mortem use this logging work exists for) sees two incidents about a second apart. The first is named after a Go function and does not say what the daemon did about it. The two reads also disagree about a missing file: the startup read says nothing, the cycle WARNs. The startup line tells the reader nothing the cycle's line does not. Whichever committer acts on the corrupt file first, the daemon's tick or a commit-now, logs the cycle line from the read it acts on. Restore logs its own `ReadIndex failed` under `restore:` at bootstrap.
- **Evidence**: cmd/state_daemon.go:425-430 (the daemon's startup `state.ReadIndex`, WARN at :429); internal/state/commit_cycle.go:121-126 (the cycle's read under the lock, and `logUnreadIndex` on a nil prior) and :156-163 (`logUnreadIndex`); cmd/state_commit_now.go (commit-now's equivalent `loadPrevIndex` WARN, deleted by this phase in c40f8965e); internal/restore/restore.go:107 (restore's own report of the same file at bootstrap).
- **Proposed shape**: Remove the `else if err != nil { logger.Warn("ReadIndex failed", "error", err) }` branch from the daemon's startup read. Keep the read itself as the PrevIndex seed: `if idx, skip, _ := state.ReadIndex(dir); !skip { prevIdx = &idx }`. A non-nil error always comes with `skip` set, so ignoring it changes no seed. No test pins the startup line (`rg -n 'ReadIndex failed' --type go` finds only this site and restore.go:107). The one observable change is that the duplicate WARN no longer appears.

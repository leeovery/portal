SUMMARY: The production code matches the specification and its corrigenda throughout. The committing path lists sessions through ListSessionNamesProbe while restore, the resolver, completion and the picker keep the shared listing. The own-server confirmation (display-message '#{pid}' checked against the pid in TMUX) runs after the last capture read and before any link or re-file, and a failed capture is classified by that confirmation. The re-file is a hard link, so a cycle that ends uncommitted names only files on disk. Empty captures go through the cycle's ScrollbackWriter, which judges them at the transcript the record names; an answered lazy pane stays on its token-named transcript until a dump writes its capture. The eager and parked shells catch TERM and leave HUP uncaught, the draw and the waiter catch SIGTERM, and the parked shell's draw loop covers the moment before each catch is installed. Drop and back-off lines use only the session, pane_key and error keys, at INFO or above. The cycle 1 test finding (commit-now failed-listing subtest) and both comment corrections are in the tree, and CLAUDE.md's changed passages agree with the code. One divergence was weighed and not written, because it falls below the floor. An ordinary pane moved since its last commit (a session rename) has its empty capture judged at its new positional path, not at the file its last committed record names. The loss needs tmux to begin exiting during the dump of the commit that follows the rename, about a second later.

AGENT: architecture
FINDINGS: none
SUMMARY: The save-path changes compose cleanly. Every committer reaches capture, re-file, dump and commit only through RunCommitCycle, and the guard covers both Commit and WriteScrollbackIfChanged. The own-server confirmation is defined once (confirmOwnServer) and serves the cycle's confirmation, the failed-capture classification and the per-pane empty-capture check alike. The answered-pane hold is computed against the same on-disk index the drop logging measures, and that index is never aliased by the merges. The SIGTERM hardening routes the eager pane, the answered lazy pane and the parked chain through the shared hookExecArgs, paneStillPending and catchSIGTERM pieces rather than separate copies. Every candidate I examined either fails closed and loudly, or has no realistic production trigger: an unknown own server, commit-now's LoadPrev fallback re-reading sessions.json only to log the reason, the writer deriving the saved path from the positional-or-held invariant, and the window-layout identity used to tell a rename from a drop. None cleared the floor.

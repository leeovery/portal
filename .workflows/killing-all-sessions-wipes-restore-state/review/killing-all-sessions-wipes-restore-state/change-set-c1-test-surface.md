FINDINGS:
- [in-scope] [spreading] internal/state/commit_rename_realtmux_test.go:64 — The unit-lane test writes a line to the developer's real `~/.zsh_history` on every run. It creates its sessions with no command (lines 27, 49), so each pane runs the developer's login `$SHELL` (zsh). The `internal/state` TestMain (internal/state/testmain_isolation_test.go) only poisons the PORTAL_* paths and never re-points `HOME` or `ZDOTDIR`, so those shells resolve `/etc/zshrc`'s `HISTFILE=${ZDOTDIR:-$HOME}/.zsh_history` to the developer's own file. `movePaneOn` then types `cd <tempdir> && exec sleep 30` into one of them, and zsh saves its history when it `exec`s. Measured: `grep -a -c 'TestCommitRealTmuxTellsARenameFromADropBesideANewSession' ~/.zsh_history` → 114 entries, dated from 2026-10-06 11:02 (the day the test landed) to 2026-10-07 16:17. The pre-existing sibling `capture_period_session_realtmux_test.go` types `echo` with no `exec` and leaves 0 entries. Two fixes are defensible. One is to isolate the shell environment before the server starts: `portaltest.IsolateStateForTest(t)` ahead of `tmuxtest.New`, which `t.Setenv`s `HOME`, `ZDOTDIR` and `HISTFILE=/dev/null`, and the server and its login shells inherit them. The other is to stop typing into an interactive shell and move the pane on with `respawn-pane -k -c <dir> … sleep 30` rather than `send-keys … exec sleep 30`. No test observes the developer's history, so the fix needs a deliberate check — FAILS: every `go test ./...` or `go test ./internal/state` writes another line to the developer's live shell history, which breaks CLAUDE.md's absolute rule that a test never affects the filesystem outside its temp dirs. Shells sharing that history (or a later Ctrl-R or up-arrow) offer `cd /Volumes/Scratch/tmp/… && exec sleep 30`, and recalling it replaces the user's shell with `sleep 30`, which closes their pane 30 seconds later. Every run also sources the developer's own zsh startup files under the test's tmux server
